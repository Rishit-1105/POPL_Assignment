# Prompts used for Problem 2 (Prolog)

Each prompt below is the text given to the AI assistant, in the order used. The line under each prompt says what it was for.

## Prompt 1

```
I've attached my assignment PDF. I'm working on Problem 2 (the Prolog equation problem) in
code/id_q2.pl on this branch. Please read that section first, but don't solve all of it yet,
because I'm doing it one predicate at a time.

For now, just write expr_string(Tree, String) in code/id_q2.pl. A tree is either a number or
op(O,A,B) where O is +, -, * or /. It should turn the tree into a string (an SWI-Prolog string,
not an atom) with no spaces, using the parenthesis rules from the "canonical form" part of the
problem. For example, op(*,op(+,4,2),3) should give "(4+2)*3" and op(-,1,op(-,2,3)) should
give "1-(2-3)".

Only write this one predicate, no tests, and follow the file rules in the PDF (definitions only,
no initialization directive). Please commit it when it works.
```

Purpose: writes `expr_string/2`, which turns an expression tree into the canonical equation text with the required parentheses.

## Prompt 2

```
I'm continuing Problem 2 from the attached PDF in code/id_q2.pl. Please don't change what's
already there. Add one predicate, apply_op(O, A, B, V), which gives V as the result of A O B,
where O is +, -, * or /. For division, it should only work when B isn't zero and the division
is exact, as the problem says. Otherwise it should just fail, without an error. Only this one
predicate, no tests. Commit it when it works.
```

Purpose: writes `apply_op/4`, which does one arithmetic step and rejects division by zero or inexact division.

## Prompt 3

```
I'm continuing Problem 2 from the attached PDF in code/id_q2.pl. Please don't change what's
already there. Add one predicate, expr_over(List, Tree, Value). Given a non-empty list of
integers, it should find every expression tree you can build using each number exactly once, in
the given order, with +, -, *, / and any bracketing. The tree uses the same format as
expr_string (a number, or op(O,A,B)), and Value is what it evaluates to, using apply_op so
invalid divisions are skipped. A single number is its own tree. Only this one predicate, no
tests. Commit it when it works.
```

Purpose: writes `expr_over/3`, which enumerates every valid expression tree (and its value) over a list of numbers in order.

## Prompt 4

```
I'm continuing Problem 2 from the attached PDF in code/id_q2.pl. Please don't change what's
already there. Add one predicate, generate_equation(List, Equation). It should split the list
into a non-empty left part and a non-empty right part, find an expression for each side using
expr_over so that both sides have the same value, and give the equation as a string like
"4*2=5+3" using expr_string for each side. It must simply fail (no error, no infinite loop) if
there is no valid equation, including for lists of length 0 or 1. Only this one predicate, no
tests. Commit it when it works.
```

Purpose: writes `generate_equation/2` (P2.a), which returns one valid equation string for a list, or fails if none exists.

## Prompt 5

```
I'm continuing Problem 2 from the attached PDF in code/id_q2.pl. Please don't change what's
already there. Add one predicate, all_equations(List, Equations), which gives the list of all
valid equations for the list (using generate_equation). The list must have no duplicates and be
sorted with sort/2. If there are none, it should be the empty list. Only this one predicate, no
tests. Commit it when it works.
```

Purpose: writes `all_equations/2` (P2.b), which collects all valid equations, sorted and without duplicates.

## Prompt 6

```
In code/id_q2.pl, add count_equations(List, N), where N is the number of equations in the list
given by all_equations. Only this predicate, don't change anything else. Commit it when it works.
```

Purpose: writes `count_equations/2`, which gives how many distinct valid equations a list has.

## Prompt 7

```
For Problem 2 from the attached PDF, create tests/id_q2_tests.pl. It should load code/id_q2.pl
and check the examples from the PDF: generate_equation([4,2,5,3],E) works; all_equations of
[4,2,5,3] gives exactly the seven equations listed, and the count is 7; generate_equation fails
for [2,3,4] while all_equations gives []; all_equations([2,4,8],Es) gives ["2*4=8"]. Also add a
few edge cases of your own: the empty list, a one-element list, [0,0], and a list that could
divide by zero like [5,0,0]. Make the tests print PASS or FAIL for each case. Only this one
test file, don't change the code. Commit it when it works.
```

Purpose: creates the Problem 2 test file with the PDF examples and extra edge cases.
